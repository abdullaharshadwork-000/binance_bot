# Code review findings

Reviewed 2026-09-23. This is a code review and offline fault-injection audit, not a guarantee that every bug has been found. No real orders or credentialed API requests were made. Application code was not changed during this review. The existing suite passes: 11 tests.

Evidence: **Reproduced** means an isolated Python check with temporary databases and mocked exchange methods demonstrated the behavior. **Code** means the defect follows from the inspected control flow; its end-to-end exchange/browser manifestation was not exercised.

Additional operational limitations, distinguished from the defects above:

- Stops are local software checks, not exchange-resident protective orders. Stop Bot, process failure, loss of market data, and machine/network outages leave a real position without this bot's protection. The default launcher also enables auto-reload, and restarting the application does not automatically resume monitoring (`run.py:4`, `app/agents/orchestrator.py:48`, `app/execution/broker.py:131`).
- State-changing API routes have no authentication. The supplied launcher binds localhost, limiting remote exposure; exposing it via another bind address/proxy would expose trading controls (`app/main.py:137`).
- Configured risk sizing excludes fees and slippage and checks a realized daily-loss threshold before entry; these are not guaranteed maximum-loss bounds (`app/risk/manager.py:35`).

External contract references used in review:

- [Binance timeout and HTTP error semantics](https://developers.binance.com/en/docs/products/spot/rest-api): timeouts and 5xx responses can leave execution status unknown; query status before treating an order as failed.
- [Binance filters](https://developers.binance.com/en/docs/products/spot/filters): market quantity limits and notional applicability.
- [Binance order response fields](https://developers.binance.com/en/docs/catalog/core-trading-spot-trading/api/rest-api/trade): executed quantity, order status, and per-fill commission asset.

Priority: isolate modes and assets, serialize order/lifecycle operations, implement durable order reconciliation and actual-fill accounting, then fix monitoring and signal consistency. Extend regression coverage around these cases before relying on the existing passing suite.
